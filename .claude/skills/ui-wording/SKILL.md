# UI 文言の見直し

軽音サークルのメンバーが、説明なしで一読して意味がわかる文言にする。
**足すより削る。迷ったら短いほう。**

## 手順

1. 今回の変更で増えた・変わった表示文字列を全部抜き出す
   ```bash
   git diff -U0 -- v3 | grep -E '^\+' | grep -v '^+++'
   ```
   コメント（`//` `/* */` `<!-- -->`）は対象外。対象は画面に出る文字列だけ
2. 1つずつ下のチェックにかけ、引っかかったら直す
3. 直した前後を一覧でユーザーに見せる（「前 → 後」の形で、理由は一言）

## チェック

### A. 書かなくていいものを削る
- **アイコン・見た目でわかることを書いていないか**（「ここをタップすると表示されます」は書かない。押せばわかる）
- **中の仕組み・運営の事情を書いていないか**
  - NG:「（NAVITIME は月500回まで）」「Google を経由して取り込みます」の仕組み説明
- **括弧の補足はないか**。要るなら本文に入れ、要らないなら消す
  - NG:「URL でカレンダーを追加（購読）」→ OK:「URL でカレンダーを追加」
- **読み手を「〜の人」で分けていないか**。条件で書く
  - NG:「Android の人 … 」→ OK: 何をすればいいかだけを書く
- **同じことを2回言っていないか**（見出しと本文、ラベルと ⓘ で重複）
- **長い補足**はⓘ（`tip_attr` / `data-tip-from`）に逃がせないか

### B. 言葉をそろえる
- **1つのものに1つの言葉**。既存の画面で使っている語を `grep` で確かめてから使う
  - 例:「同期」と「連携」、「毎週」と「繰り返し」、「予定あり」と「予定」を混ぜない
- **内輪・コードの言葉を使わない**。使う人の言葉にする
  - NG:「呼ばれた人の自宅の駅」→ OK:「メンバーの最寄り駅」
  - NG: テーブル名・変数名・`poll` `ical` などの英単語をそのまま
- 区切りは「 / 」で統一（例:「Google / iPhone」）。「・」で何個もつながない

### C. 書き言葉にする（口語を使わない）
| 口語（NG） | 書き言葉（OK） |
|---|---|
| まるごと／全部 | すべて |
| ちょっと／少し | 一部／（数値で書く） |
| いちばん | 最も |
| 〜けど／〜けれど | 〜が |
| 〜しちゃう／〜しとく | 〜する／〜しておく |
| 〜じゃない | 〜ではない |
| 〜なので（文頭の「なので」） | そのため |
| 〜とか | 〜など |
| どっち／どれくらい | どちら／どの程度 |
| だれ／いつでも OK | 誰／いつでも可 |

- 話しかける調子（「〜してね」「〜しよう！」）にしない
- 感嘆符・「〜！」を UI に使わない

### D. 不自然な日本語を直す
| NG | OK |
|---|---|
| 〜することができます | 〜できます |
| 〜を行う／〜を実施する | 〜する |
| 〜となります | 〜です |
| 〜したい場合は | 〜するには |
| 〜されています（不要な受け身） | 〜しています／〜です |
| 〜について | （たいてい削れる） |
| 〜してください。〜してください。 | 手順は番号付きの体言止めに |
| 1日まるごと（口語・あいまい） | その日のすべての時間帯 |
| 〜的な／〜という形で | 削る |
| あなたの〜 | 削る（主語は書かない） |

- **翻訳調にしない**。英語の UI 文を訳したような語順（「〜するために、〜を選択してください」）は、日本語の UI で普通に見る言い方に置き換える
- **文末をそろえる**: 見出し・ボタン・ラベル・手順は体言止め、説明文は「です・ます」。1つのブロックで混ぜない
- **カタカナ語**は日本語で通じるなら日本語（「ステータス」→「状態」）。ただし Google・iPhone など固有名詞と、定着した語（スタジオ・セトリ）はそのまま

### E. 最後に
- 声に出して読み、引っかかる所がないか
- 初めて使う人が説明なしで意味がわかるか
- 削っても意味が通るなら、削る
